# MissionManager

本地优先的 YAML 任务排期管理器。第一阶段已实现：

- 0.5 天（上午 / 下午）排期和完成后开始依赖
- 无限层级的父子任务；父任务自动汇总后代叶子任务的排期，只有叶子任务参与排期和依赖
- 中国大陆年度放假、调休日历联网获取与本地整日修正
- 天、周、半月、月、季度、半年、年七种时间轴
- 任务状态底色、截止时间预警、标签筛选和未匹配任务灰显
- 甘特图拖动开始时间、保持预计耗时、调整右边界耗时
- 右键拖动或详情面板新增依赖，循环依赖和违反依赖的拖动会被阻止
- YAML 草稿、保存并备份、备份恢复、外部修改检测

## 启动

本机的独立 Node.js 运行环境和依赖已经准备好，可以直接运行：

```bash
cd /home/jiapengli/Desktop/code/MissionManager
bash run.sh
```

脚本优先使用系统 Node.js，当前机器没有系统 Node.js 时使用项目 `.runtime/` 中的独立环境，不修改系统安装。

依赖管理脚本：

```bash
# 新环境：下载 Node.js（系统没有时）、安装锁定版本依赖并构建
bash create_dependence.sh

# 清除 .gitignore 中的可再生内容
bash clear_dependence.sh

# 启动；缺少依赖时会自动调用 create_dependence.sh
bash run.sh
```

`clear_dependence.sh` 只清理可再生的依赖、运行时、构建和测试输出，不删除源码、`package-lock.json`、项目 YAML、备份或配置脚本。

在其他机器上需要 Node.js 20.19+ 或 22.12+，建议使用 Node.js 22 LTS。

```bash
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:4310`。默认项目文件是 `data/project.yaml`，也可以用环境变量指定：

```bash
MISSION_FILE=/path/to/project.yaml npm run dev
```

生产构建：

```bash
npm run build
npm start
```

## 操作约定

编辑和拖动先更新界面草稿；点击“保存并备份”或按 `Ctrl+S` 后才写入 YAML，并生成快照。外部文件发生变化时，没有本地草稿会自动刷新；有本地草稿会暂停保存并提示重新加载。

本地日历从 `holiday-cn` 获取年度中国大陆全国统一放假、调休数据。断网时使用 YAML 中已保存的年度快照；未加载的年份按普通周末暂估并显示提示。手动修正优先于联网数据，并与任务一起保存。

任务块状态色可在 YAML 的 `project.status_colors` 中配置；每种状态需要 `fill`（填充色）、`border`（边框色）和 `text`（文字色），均为 `#RRGGBB`：

```yaml
project:
  status_colors:
    未开始: { fill: "#dfe9e2", border: "#c8d8cb", text: "#647c69" }
    进行中: { fill: "#bce0d5", border: "#92c7b7", text: "#2a7361" }
    验收中: { fill: "#e5ddf4", border: "#d0bfe7", text: "#8264a3" }
    已完成: { fill: "#d4e3f5", border: "#b9cfe9", text: "#567ba2" }
```

缺少该字段的旧项目会自动使用上述默认颜色。

## 第一阶段边界

- 提供数百条任务的基础实现，尚未对数千条任务和长达几十年的细粒度视图做性能优化。
- UI 固定一次打开一个 YAML；切换项目通过重启时设置 `MISSION_FILE`。文件必须事先存在。
- 日历联网更新从“本地日历”手动触发；示例没有预装年度数据，第一次使用建议加载排期涉及的年份。
- 未匹配标签的任务仍参与计算。执行人和状态只是信息，不自动错峰或冻结排期。
- 年度日历目前只支持全国统一安排，不包含地方及特定人群假期。
- 右键拖动依赖不自动滚屏；远距离任务可以通过详情面板选择前置任务。
- 极短任务最少显示 8 像素，完整名称保留在左侧任务列；精确拖动建议使用天、周视图。
- YAML 保存会统一排版，不保留注释；无法识别的字段会阻止保存，避免静默丢弃数据。
- 备份位于 `data/backups/<文件名>/`，保留初始文件和每次保存的快照，不会被依赖清理脚本自动删除。
- 外部编辑器不受本程序锁控制；保存前会检查内容版本，适合本机单人使用，不提供多进程事务或协同编辑。
- 不提供细粒度撤销、导出、批量移动或人员资源排期。

## 建议的人工验收

1. 打开示例，点击任务条改名称、状态和半天耗时，确认保存前原 YAML 不变。
2. 使用 Ctrl+S 保存，检查主文件和备份；从“备份历史”恢复一个版本。
3. 在天视图拖动任务，向前拖过依赖边界应被阻止；延长前置任务应使后续任务顺延。
4. 右键从前置任务拖到后续任务，检查箭头方向、依赖列表以及循环依赖提示。
5. 在本地日历将工作日设为休息日，比较允许与不允许休息日工作的任务。
6. 使用外部编辑器修改 YAML，分别验证无草稿时自动刷新、有草稿时冲突提示。

# TaskManager

本地优先的 YAML 任务排期管理器。第一阶段已实现：

- 0.5 天（上午 / 下午）排期和完成后开始依赖
- 无限层级的父子任务；父任务自动汇总后代叶子任务的排期，只有叶子任务参与排期和依赖
- 中国大陆年度放假、调休日历联网获取与本地整日修正
- 天、周、半月、月、季度、半年、年七种时间轴
- 时间轴支持 50%—400% 水平缩放，便于查看和拖动半天任务
- 任务状态底色、截止时间预警、标签筛选和未匹配任务灰显
- 甘特图拖动开始时间、保持预计耗时、调整右边界耗时
- 右键拖动或详情面板新增依赖，循环依赖和违反依赖的拖动会被阻止
- YAML 草稿、保存并备份、备份恢复、外部修改检测
- 单文件交互式 HTML 导出，可离线查看任务详情、依赖高亮、折叠、筛选、缩放和平移
- 项目级执行人管理，以及确定性的“同执行人任务不可并行”资源排程

## 启动

本机的独立 Node.js 运行环境和依赖已经准备好，可以直接运行：

```bash
cd /home/horizon/Desktop/code_space/Task_Manager
bash run.sh
```

脚本优先使用系统 Node.js，当前机器没有系统 Node.js 时使用项目 `.runtime/` 中的独立环境，不修改系统安装。

依赖管理脚本：

```bash
# 新环境：下载 Node.js（系统没有时）、安装锁定版本依赖并构建
bash create_dependence.sh

# 清除 .gitignore 中的可再生内容
bash clear_dependence.sh

# 启动；缺少依赖时会自动调用 create_dependence.sh
bash run.sh
```

`clear_dependence.sh` 只清理可再生的依赖、运行时、构建和测试输出，不删除源码、`package-lock.json`、项目 YAML、备份或配置脚本。

在其他机器上需要 Node.js 20.19+ 或 22.12+，建议使用 Node.js 22 LTS。

```bash
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:4310`。默认项目文件是 `data/example_project.yaml`，也可以用环境变量指定：

```bash
TASK_MANAGER_FILE=/path/to/project.yaml npm run dev
```

顶部“项目文件”选择器会列出启动项目文件同目录下的所有 `*.yaml` 文件。默认情况下只需将 `project_c5.yaml`、`project_j30.yaml` 等文件放入 `data/`，即可在界面中切换；每个项目使用独立的备份目录。

生产构建：

```bash
npm run build
npm start
```

## 操作约定

编辑和拖动先更新界面草稿；点击“保存并备份”或按 `Ctrl+S` 后才写入 YAML，并生成快照。外部文件发生变化时，没有本地草稿会自动刷新；有本地草稿会暂停保存并提示重新加载。

点击顶部操作区的“导出交互式 HTML”会下载一个自包含的只读 `.html` 文件。文件内嵌当前项目草稿、计算排期、样式和交互代码，不依赖服务器或网络；悬浮任务只高亮直接依赖而不隐藏其他任务，单击叶子任务后隐藏无关任务并显示详情。在聚焦模式中，点击父任务、空白处、时间轴、工具栏、标题或详情区域等任意非叶子任务位置都会恢复完整视图；拖动画布不会退出聚焦。除叶子任务条和按钮外，甘特图区域均可作为拖动起点，父任务条和父任务名称区域也可以直接拖动。父任务在非聚焦状态下不响应任务条或名称单击，只保留左侧按钮的展开、折叠功能。导出不会写入 YAML，存在未保存修改时，文件顶部会标明包含草稿。

所有下拉框都支持直接输入搜索：中文、英文（忽略大小写）、拼音全拼、空格分隔拼音和拼音首字母。例如“需求梳理”可以输入 `需求`、`xuqiushuli`、`xu qiu` 或 `xqsl`；父任务和前置任务还可按 UID、排序 ID 搜索。匹配保持原有选项顺序，只能选择已有选项，不会创建新值。

点击选择框或通过 `Tab` 聚焦后输入，用 `↑` / `↓` 移动候选项，`Enter` 或鼠标点击确认。`Esc`、`Tab` 或点击外部取消未确认的搜索并保留原值；清空搜索词仅恢复全部候选项。输入法组词期间的 Enter 不会提交选择。搜索本身不修改项目，也不会切换项目文件；拼音匹配完全在本地运行，不需要联网。

通过详情面板设置父任务，或按住 `R`，从子任务块右键拖到目标父任务块（也可拖到左侧任务行）。拖动开始后会显示紫色箭头；松开右键确认，`Esc` 或落到空白处取消。不按 `R` 的右键拖动用于添加依赖：从需要等待的任务 A 拖到前置任务 B，表示 A 依赖 B；拖动时箭头从 B 反向指向 A。

任务详情顶部的“关系拖拽区”提供相同操作：从这里普通右键拖到前置任务，会让当前任务依赖目标任务；按住 `R` 再右键拖动，会把目标任务设为当前任务的父任务。父任务本身只支持按住 `R` 调整父级，不能创建普通依赖。拖动期间详情面板保持打开。

已有前置依赖的任务首次成为父任务时，其全部前置依赖会迁移给第一个子任务，与该子任务原有依赖合并去重，并清空父任务的依赖；后续子任务不再继承。解除父子关系不会自动恢复这些依赖。循环关系、其他任务仍依赖目标父任务、接收依赖的子任务自身已有子任务等非法情况会被整体拒绝，不会留下部分修改。

本地日历从 `holiday-cn` 获取年度中国大陆全国统一放假、调休数据。断网时使用 YAML 中已保存的年度快照；未加载的年份按普通周末暂估并显示提示。手动修正优先于联网数据，并与任务一起保存。

任务块状态色可在 YAML 的 `project.status_colors` 中配置；每种状态需要 `fill`（填充色）、`border`（边框色）和 `text`（文字色），均为 `#RRGGBB`：

```yaml
project:
  status_colors:
    未开始: { fill: "#dfe9e2", border: "#c8d8cb", text: "#647c69" }
    进行中: { fill: "#bce0d5", border: "#92c7b7", text: "#2a7361" }
    验收中: { fill: "#e5ddf4", border: "#d0bfe7", text: "#8264a3" }
    已完成: { fill: "#d4e3f5", border: "#b9cfe9", text: "#567ba2" }
```

缺少该字段的旧项目会自动使用上述默认颜色。

执行人由项目级名单限定；在任务详情中只能从下拉框选择：

```yaml
project:
  assignees: [小林, 小陈, 你, 测试员]
```

任务中的 `assignee` 必须是此名单的成员。旧项目缺少 `assignees` 时，会根据已有任务自动生成名单，并会在下次保存时写入 YAML。

点击顶部导航中的“项目设置”可以修改项目名称、`start_date`、同执行人排期策略，并增删执行人。正在被任务使用的执行人不能直接删除，需要先在任务详情中重新分配；项目至少保留一名执行人。

默认勾选“允许同一个执行人同时有并行任务”，与旧版本行为一致。取消该勾选后，系统对叶子任务执行确定性的资源受限列表排程：显式依赖决定任务何时进入候选集合，最早可开始时间优先，开始时间相同时再按排序 ID 选择：

```yaml
project:
  allow_assignee_parallel_tasks: false
```

排程会保证同一执行人的任务不重叠，并在实际相邻的任务间生成资源顺序关系。该关系参与依赖聚焦、主甘特图和交互式 HTML 导出，以蓝灰色虚线显示，但不会写入任务的 `dependencies`。显式依赖始终优先于排序 ID，因此即使后排任务是前排任务的前置条件，也不会生成回环。父任务只汇总后代排期，不占用执行人资源。

新建任务的可编辑默认值由根目录的 `task_defaults.yaml` 提供。每次点击新建时都会重新读取，因此修改后无需重启：

```yaml
name: 新任务
description: ""
assignee: null            # null 表示使用当前项目的第一个执行人
status: 未开始
earliest_start: null
latest_finish: null
duration_days: 2
collapse_children: false
labels: []
allow_rest_day_work: false
```

UID、排序 ID、父任务和依赖关系不在模板中，始终由系统为新任务生成。如果 `assignee` 填写了具体姓名，该值必须存在于当前项目的 `assignees` 名单中。模板缺少字段、存在未知字段或值无效时，新建操作会被拒绝并在界面显示错误。可通过 `TASK_MANAGER_DEFAULTS_FILE=/path/to/defaults.yaml` 使用其他模板路径。

## 第一阶段边界

- 提供数百条任务的基础实现，尚未对数千条任务和长达几十年的细粒度视图做性能优化。
- 项目选择器只显示启动项目文件所在目录的顶层 `*.yaml` 文件；文件必须事先存在，不提供界面内新建或跨目录浏览。
- 日历联网更新从“本地日历”手动触发；示例没有预装年度数据，第一次使用建议加载排期涉及的年份。
- 未匹配标签的任务仍参与计算。状态只是信息；执行人是否自动错峰由项目的同执行人排期策略决定。
- 年度日历目前只支持全国统一安排，不包含地方及特定人群假期。
- 右键拖动依赖不自动滚屏；远距离任务可以通过详情面板选择前置任务。
- 极短任务最少显示 8 像素，完整名称保留在左侧任务列；精确拖动建议使用天、周视图。
- YAML 保存会统一排版，不保留注释；无法识别的字段会阻止保存，避免静默丢弃数据。
- 备份位于 `data/backups/<文件名>/`，保留初始文件和每次保存的快照，不会被依赖清理脚本自动删除。
- 外部编辑器不受本程序锁控制；保存前会检查内容版本，适合本机单人使用，不提供多进程事务或协同编辑。
- 不提供细粒度撤销、导出、批量移动或人员资源排期。

## 建议的人工验收

1. 打开示例，点击任务条改名称、状态和半天耗时，确认保存前原 YAML 不变。
2. 使用 Ctrl+S 保存，检查主文件和备份；从“备份历史”恢复一个版本。
3. 在天视图拖动任务，向前拖过依赖边界应被阻止；延长前置任务应使后续任务顺延。
4. 右键从前置任务拖到后续任务，检查箭头方向、依赖列表以及循环依赖提示。
5. 在本地日历将工作日设为休息日，比较允许与不允许休息日工作的任务。
6. 使用外部编辑器修改 YAML，分别验证无草稿时自动刷新、有草稿时冲突提示。

## 遗留问题

- 表示依赖关系的箭头，会被多层父级别依赖关系遮挡。并且，父任务中子任务的依赖关系箭头颜色太浅了，需要和正常的依赖关系一样显眼
